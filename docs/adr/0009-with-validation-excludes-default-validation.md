# `WithValidation()` always excludes the default validation stage

`ConduitPipeBuilderExtensions.WithValidation()` lets a pipe explicitly add a `ValidationStage<TRequest, TResponse>` at a chosen point in its stage order, but it only ever called `AddStage`. It never touched `ExcludeValidation()`, so a pipe that called `WithValidation()` without also separately calling `ExcludeValidation()` got validated twice: once by the default pre-execution stage every pipe gets by default, and again by the explicitly added stage. For a valid request this silently ran the same validator's `ValidateAsync` twice with no visible symptom beyond wasted work; a validator with side effects (e.g. one that calls out to another service) would run those side effects twice per request.

We change `WithValidation()` to call `self.ExcludeValidation()` before adding its own stage, so calling it is enough on its own to guarantee exactly one validation stage runs, at the position the caller chose — regardless of whether they also called `ExcludeValidation()` themselves. Not doing this — e.g. detecting the default stage is already present and no-op'ing instead — was rejected: `WithValidation()` exists specifically so a caller can put validation somewhere other than the default position, and silently declining to add the stage would drop that intent entirely.
