# DebugPreExecutionStage/DebugPostExecutionStage only wire in when the log level is Debug

`DebugPreExecutionStage<,>` and `DebugPostExecutionStage<,>` exist purely to write a `Logger.Debug(...)` line before and after a pipe's other stages. `ReflectionHelper.GetServiceDescriptorsForHandler` has always registered them as DI-resolvable closed generics for every `RegisterHandler` pair, but nothing ever added their types to `DefaultPipeConfiguration.PreExecutionStages`/`PostExecutionStages` — the lists that actually decide which stages a pipe runs. They were dead: constructible, never constructed.

Simply wiring them in unconditionally was rejected. `Log.WriteMessage` already drops anything below the configured `IEnvironment.LogLevel` (see `Log.AllowedToLog`), so at any level above Debug these stages would run — full DI resolution, `ExecuteStage`'s try/catch and logging around it, a `StageResult` allocation — purely to produce a message the logger throws away. That's pipe-execution overhead on every request for output nobody sees.

`ConduitConfigurationBuilder`'s constructor now checks `IEnvironment.LogLevel` once, at configuration time, and only then adds `DebugPreExecutionStage<,>`/`DebugPostExecutionStage<,>` to the default stage lists. Below Debug, `RegisterHandler` and `RegisterPipe` pipes never see these stage types at all, matching the "no work for suppressed output" intent. Because `DefaultPipeConfiguration`'s stage lists are shared between both registration paths, the same conditional wiring covers `RegisterPipe` pipes too — which is also why the stages are additionally registered as open generics (`typeof(DebugPreExecutionStage<,>) -> typeof(DebugPreExecutionStage<,>)`), the same pattern [ADR-0007](0007-configuration-interfaces-own-their-real-surface.md)'s `AddValidation` already uses for `ValidationStage<,>`: `RegisterPipe` never registers a closed stage type for its own pair the way `GetServiceDescriptorsForHandler` does for `RegisterHandler`, so without the open-generic registration, DI would fail to resolve the stage for any `RegisterPipe`-registered pair and throw `StageNotFoundException` the moment `LOG_LEVEL=Debug` was set.

`IEnvironment` isn't otherwise injectable into `ConduitConfigurationBuilder` (no DI container exists yet at configuration time — the same reason `HashUtil.Instance` is used directly elsewhere in this class), so the constructor takes an optional `IEnvironment` for tests and defaults to `new EnvironmentImpl()` (reads `LOG_LEVEL`) when not supplied.
